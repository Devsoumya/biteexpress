# ADR-001: Data model

## Context

The source is the Zomato CSV: 9,551 rows, 21 flat columns. Profiling it shaped most of the rules below:

- **0 means unknown, in three places.** 2,148 rows have rating 0, meaning "not enough ratings": 1,054 of them have 1–3 votes, and no rated row has fewer than 4. 497 rows sit at coordinates 0,0, and 18 have cost 0.
- **The `Currency` column can't be trusted.** "Dollar($)" covers four countries, and code 162 (the Philippines) is labelled "Botswana Pula". Each of the 141 cities belongs to exactly one country, so the country is reliable.
- **The file is valid UTF-8 with upstream damage:** three city names and two cuisines contain U+FFFD, and Turkish `ı` is systematically stored as `۱`.
- **Names carry food signal the cuisine column doesn't:** 13 names contain "Vada Pav" and 124 contain "Biryani".

The workload is read-heavy lists, filtered and sorted many ways; writes are rare.

## Decision

One document per restaurant in a `restaurants` collection, reshaped from the flat CSV.

### The document

```jsonc
{
  "_id": ObjectId("…"),          // exposed as `id` (24 hex characters)
  "tenantId": "biteexpress",     // set by the repository, never by the client
  "sourceId": 3400341,           // the CSV's Restaurant ID; absent for restaurants created through the API
  "name": "Goli Vada Pav No. 1",
  "address": {
    "line": "Shop 12, Sector 29 Market",
    "locality": "Sector 29",     // optional
    "city": "Gurgaon"            // as written; the filter key is norm.city
  },
  "country": { "code": "IN", "name": "India" },
  "location": { "type": "Point", "coordinates": [77.0688, 28.4595] },   // [lng, lat]; omitted when unknown
  "cuisines": ["Street Food", "Fast Food"],                              // display values; [] when unknown
  "cost": { "averageForTwo": 300, "currency": "INR", "priceRange": 1 },  // averageForTwo omitted when unknown
  "features": { "tableBooking": false, "onlineDelivery": true, "deliveringNow": false },
  "rating": { "average": 3.6, "votes": 112 },                            // average omitted when unrated
  "norm": { "city": "gurgaon", "cuisines": ["street food", "fast food"] }, // canonical filter keys
  "createdAt": ISODate("…"),
  "updatedAt": ISODate("…"),
  "schemaVersion": 1
}
```

| Field                          | Type                | Required                    | Notes                                                          |
| ------------------------------ | ------------------- | --------------------------- | -------------------------------------------------------------- |
| `_id`                          | ObjectId            | yes                         | Generated by the driver                                        |
| `tenantId`                     | string              | yes                         | First key of the unique index and of every query               |
| `sourceId`                     | int                 | no                          | Unique per tenant (partial index); the seed upserts on it      |
| `name`                         | string, 1–200       | yes                         | Matched by the search analyzers (folding, autocomplete, fuzzy) |
| `address.line`, `address.city` | string              | yes                         | `address.locality` is optional                                 |
| `country.code`, `country.name` | ISO alpha-2, string | yes                         | From the country table, never from the client's spelling       |
| `location`                     | GeoJSON Point       | no                          | Longitude −180..180, latitude −90..90; no 0,0                  |
| `cuisines`                     | string[]            | yes (may be empty)          | Unique; display spelling kept                                  |
| `cost.currency`                | ISO 4217            | yes, when `cost` is present | From the country table                                         |
| `cost.averageForTwo`           | number > 0          | no                          | Never 0                                                        |
| `cost.priceRange`              | int 1–4             | no                          | Zomato's budget tier                                           |
| `features.*`                   | boolean             | no                          | `deliveringNow` is a CSV snapshot                              |
| `rating.average`               | number, 0 < x ≤ 5   | no                          | Never 0; absent means unrated                                  |
| `rating.votes`                 | int ≥ 0             | yes                         | 0 for a new restaurant                                         |
| `norm.city`, `norm.cuisines`   | string, string[]    | yes                         | Built only by `normalize()`; never accepted from clients       |
| `createdAt`, `updatedAt`       | date                | yes                         | Set by the repository                                          |
| `schemaVersion`                | int ≥ 1             | yes                         | 1 today; bumped with a backfill when the shape changes         |

**Indexes on the collection:** `_id`, and `uq_tenant_source` (`{ tenantId: 1, sourceId: 1 }`, unique, partial where `sourceId` exists). Lists and search use the Atlas Search index `restaurants_search` instead (ADR-003). So the collection needs no other index.

**Schema design patterns:** Computed (`norm.*`), Extended Reference (`country.name` embedded), Schema Versioning (`schemaVersion`).

### Rules

1. **Identity.** `_id` is an ObjectId, exposed as `id`. The CSV id is kept as `sourceId`, unique per tenant through a partial unique index, so a re-seed keeps `_id` stable and API-created restaurants (which have no `sourceId`) can coexist.
2. **Absent means unknown.** `location`, `rating.average` and `cost.averageForTwo` are omitted when unknown, never 0 or null; arrays are empty. The API returns `null`.
3. **Location** is a GeoJSON `Point` (`[lng, lat]`). Exactly 0 on either axis, or out of range, counts as unknown. The same function validates POST input, where out of range is a 400.
4. **Filter keys are canonical.** `norm.city` and `norm.cuisines` come from one `normalize()` (lowercase, accents folded, whitespace collapsed, aliases resolved), used for writes and for query values. Clients never send them.
5. **Name text is not pre-processed.** Tokenizing, folding, prefixes and typo tolerance are the search analyzers' job (ADR-003), so there is no stored `nameTokens`.
6. **Country and currency** come from a 15-market table in code, keyed by the ISO code the client sends. `country.name` is stored for analytics.
7. **Grouping.** Address fields sit under `address`. `country` and `location` stay top level, because they drive currency, residency, the geo index and a future shard key.
8. **Derived presentation is not stored.** The rating label is a clean function of the average in the CSV (Poor 1.8–2.4, Average 2.5–3.4, Good 3.5–3.9, Very Good 4.0–4.4, Excellent 4.5–4.9), so the mapper computes it. The rule: store a derived value only if the database filters or sorts on it.
9. **Tenancy.** `tenantId` is on every document. The repository gets it in its constructor and adds it to every filter, write and `$search`; drafts built by the CSV mapper or POST carry no tenant, so no caller can choose one. Another tenant's id answers 404, exactly like a missing one.
10. **Carried-over fields:** `priceRange` and `features.*` are optional. `deliveringNow` is a CSV snapshot, not live availability.
11. **Seed cleanup.**
    - **Removed:** skip the junk test row (18419884), and omit rating 0, cost 0 and unknown locations.
    - **Repaired:** the 3 cities and 2 cuisines from an explicit map, `۱` → `ı` everywhere, collapsed whitespace, de-duplicated cuisines.
    - **Left alone:** the 103 names with U+FFFD, because they can't be recovered reliably.
12. **The database enforces the schema.** A `$jsonSchema` validator (`strict`, `error`) is applied idempotently by the seed. It protects the collection from every writer (the API, the seed, a future CDC consumer, ad-hoc scripts), while Zod still validates API input. A document that passes Zod but fails the validator (code 121) is a server bug: 500, with `errInfo` logged.
13. **The search index is a derived view**, updated asynchronously. POST returns the stored document and GET by id reads the collection, so a client sees its own write on those two endpoints.
14. **A rating can be carried over on create.** POST accepts an optional `averageRating` (more than 0, at most 5, rounded half-up to one decimal like the CSV) and `votes` (an integer from 0 to int32 max, default 0). A rating requires `votes ≥ 1`, because an average of no votes means nothing. Votes without a rating are valid: 1,054 CSV rows have 1–3 votes and no published average. The int32 cap exists because the driver stores a larger whole number as a double, which the validator (`int`/`long`) would reject as a 500. **Trade-off:** any caller can rate its own listing and lift it in `sort=rating` and "best" searches. That's acceptable while there is no authentication, because every caller is already trusted to create listings. With auth, rating moves to an import/admin role, or to a ratings service that owns `rating.*`. There is no update endpoint, so a rating is set once.

## Alternatives

| Option                                                | Why not                                                                                    |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Mirror the CSV, or normalize into several collections | Discovery needs everything in one read; `$lookup` adds cost for nothing                    |
| CSV id as `_id`                                       | It belongs to another system, collides across tenants, and POST would need an id generator |
| Store 0 or null for unknown                           | 0 corrupts sorts and averages; null works but is inconsistent with the other unknowns      |
| Stored name tokens with anchored regex                | Prefix only, no typo tolerance, no relevance. Atlas Search does it better                  |
| Validation in the application only                    | Protects one writer out of several                                                         |
| Collation indexes for case-insensitive matching       | Every query must pass the collation, or it silently scans                                  |

## Consequences

- **Single-document reads** feed one search index; there are no joins.
- **499 restaurants (5.2%) have no location** and can't take part in radius queries. They are listed last in distance orders within a city.
- **Changing `normalize()` needs a backfill of `norm.*`** and a `schemaVersion` bump. Changing an analyzer only rebuilds the search index.
- **Schema changes have an order:** widen the validator, deploy the writers, backfill, then tighten.

## Appendix: validator

The `$jsonSchema` validator lives in `src/db/restaurant.json-schema.ts`, the single copy used by the seed and the tests. It uses `bsonType: "number"` for numeric fields, because the driver stores whole numbers (a 4.0 rating, a 77.0 longitude) as int32.
